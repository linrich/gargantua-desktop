# Gargantua · 卡冈图雅

原生 macOS 桌面黑洞，用 Swift、AppKit、SwiftUI 和 Metal 绘制。黑洞以无边框透明窗口悬浮在桌面上，支持拖放吞入、系统废纸篓回收、鼠标穿透和可选的桌面引力透镜。

根据公开 Kerr 黑洞成像研究独立实现，包含旋转黑洞光线积分、椭圆光束滤波和镜头点扩散函数（PSF）卷积。不是 DNGR 原程序或电影官方产品；盘面材质、镜头响应和桌面扭曲包含艺术化近似。见 [模型与来源](MODEL.md)。

## 系统要求与签名

- macOS 13 或更高版本；本次提供 Apple Silicon / arm64 包，Intel 未验证。
- 从源码构建需要已完成首次启动与许可流程的 Xcode 和 Python 3；无第三方依赖下载或 API 密钥。
- 分发候选使用 ad hoc 签名，未进行 Developer ID 签名或 Apple 公证。严格签名通过不等于 Gatekeeper 放行。
- ad hoc 包的身份会随构建变化，更新后可能需要重新授予录屏权限。不要把另一份固定证书构建的授权连续性当作本包保证。

## 使用

打开后显示控制面板，菜单栏的黑洞图标可以再次打开它。关闭面板不会退出，使用菜单栏「退出 Gargantua」或面板电源按钮退出。升级前先正常退出旧实例。

「接收拖放与吞入动画」默认开启。此时悬浮窗口含透明留白会接收鼠标，黑洞可拖动、双击打开面板。直接开启「鼠标穿透」会关闭拖放接收和真实回收；需要再次拖入时手动开启接收。

「允许回收普通文件和文件夹」每次启动默认关闭，不保存开启状态。本人开启后，松手将项目移入系统废纸篓，系统报告成功后播放吞入效果，可在废纸篓中找回。关闭回收或拖放接收会取消尚未开始的项目；已完成项目仍在废纸篓中。

一次最多接收 32 项。支持本地普通文件和文件夹；符号链接、主目录、卷根目录、重复项目及父子目录重叠选择会被拒绝。部分失败会显示结果，仅成功项目播放吞入；不会改用永久删除。真实回收关闭时，文件留在原处。

主要视觉选项：

- 尺寸：默认 360 pt，可完整适配当前屏幕；不裁剪盘面、不进入独立全屏空间。
- 自旋：默认 0，范围 −0.998～+0.998；「电影参数」设为 +0.600、仰角 8°、180°快门并关闭物理频移。
- 流速：以 760 pt 下 0.05× 为基准，随尺寸补偿；可暂停时间。
- 配色：暖金、冰蓝、紫罗兰、赤焰、银白，以及色相和饱和度。
- 画质：节能、均衡、精细；内部图像上限 3840×2400，刷新目标不等于实测帧率。
- 光束与镜头：抗闪烁、光晕、快门、亮度、散射和扩散尺度；支持 [自定义 PSF](PSF-FORMAT.md)。

## 桌面采集与隐私

桌面引力透镜每次启动默认关闭。主动开启且 macOS 允许录屏后，读取黑洞所在显示器的实时画面，可能包含其他窗口和通知；排除黑洞和透镜效果窗口，保留控制台及其他窗口遮挡关系。

画面只在本机内存中用于渲染，不采集音频、不保存、不上传。最多 30 FPS；关闭透镜、强度为 0、隐藏黑洞或屏幕休眠时停止采集。暂停盘面动画时，已开启的桌面仍可实时更新。

若设置中已有许可但当前构建仍被拒绝，按面板提示为当前 App 重新授权，并退出后重新打开。系统权限操作由用户决定，程序不会重置权限。普通黑洞显示不需要录屏许可。

App 无网络请求、遥测、自动更新、全局键盘监听或辅助功能授权流程；外观保存在自己的 UserDefaults。导入 PSF 只在当前进程读取，不复制、修改或上传源文件。

## 构建与检查

在源码目录运行，输出目录必须尚不存在：

```sh
zsh Scripts/build.sh --output build/local --ad-hoc
APP_PATH="$(cat build/local/signed-app-path.txt)"
zsh Scripts/package.sh --app "$APP_PATH" --output build/Gargantua-local.zip --ad-hoc
```

App 在干净临时目录签名，随后导出至 `build/local/Gargantua.app`。打包会排除 Finder 资源属性并严格检查解包副本，不自动启动、安装或发布。`--ad-hoc` 明确跳过个人签名配置；自己的固定开发证书配置方式见 [Signing/README.md](Signing/README.md)。

```sh
zsh Scripts/check.sh quick build/quick-check
# 需要完整渲染检查时：
zsh Scripts/check.sh full build/full-check
```

quick 检查窗口/拖放集成、权限状态、生成背景透镜和单实例策略。full 追加渲染、数值参照、刷新、PSF、采样、事件及资源检查。两种模式均不采集真实桌面、不执行系统废纸篓回收、不改已安装 App。较大渲染检查会占用 GPU 内存和时间。

独立诊断入口 `--recycle-test <新目录>` 会创建并真实回收专用测试项目，不属于上述默认检查；只在明确需要测试废纸篓操作时手动运行。不要将诊断日志或包含本机路径的检查输出加入公开源码。

也可用 Xcode 打开 `Package.swift` 查看项目；Swift Package 运行不会自动采用 App 打包签名策略。
